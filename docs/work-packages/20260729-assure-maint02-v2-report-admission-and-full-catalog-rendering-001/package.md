## Purpose / Big Picture

Complete the missing maintenance path exposed by `CAL-09`: admit a new report
through one typed, auditable transaction and render every admitted V2 assurance
report through the real deterministic builder. The finished package gives
maintainers a reproducible full-catalog preview and lets readers inspect the
native-forest canopy report with its retained SVG time-series figures inline.

The stable preview root is:

```text
target/assurance-preview/usersum/assurance/reports/
```

After execution, the canopy report should be directly inspectable at:

```text
target/assurance-preview/usersum/assurance/reports/
  native-forest-canopy-phenology-evaluation/1.0.0/index.md
```

This root is disposable, ignored, non-authoritative staging. It is not the
tracked `usersum` tree and carries no publication or approval claim.

## Objective

Implement a typed new-report admission operation that atomically updates the
V2 source catalog and generated identity state, extend deterministic assembly
to render retained accessible SVG research figures, use those capabilities to
admit the completed `CAL-09` draft, and build/check the complete three-report
catalog into unrelated temporary roots and the stable preview root.

## Implementation Intent

Classification: `Critical`.

This package changes a generated-identity trust root, report schema and typed
API, transactional mutation, deterministic assembly, and a broadly consumed
CLI. It therefore requires focused adversarial tests, applicable authority and
security checks, immediate campaign-strength workspace correctness, two
independent implementation reviews, and two independent terminal
verifications.

The expected admission interface is:

```text
openwepp-assurance amend admit-report \
  --report <report-id> \
  --path <report-manifest> \
  [--if-generation <generation-id>] \
  (--check | --apply)
```

The implementer may refine option spelling only when the final interface
preserves the following contract:

- `--check` validates and plans without mutation.
- `--apply` performs one atomic catalog/lock/review-lock transaction.
- the requested ID and manifest path must agree with the validated report;
- initial admission accepts a valid, confined, unadmitted draft source and
  rejects duplicate IDs, unknown paths, path aliases, and stale generations;
- derived identities and locks are generated by the tool, never hand-edited;
- failure leaves all tracked inputs byte-identical;
- repeating an already-applied request is a deterministic no-op; and
- a successful mutation emits a canonical receipt that binds old and new
  generations, affected paths, roots, and required gates.

The expected retained-SVG assembly extension is a typed figure kind, named
deliberately during implementation, that binds:

- a content-identified public-safe SVG research object;
- a nonempty caption and meaningful alternative;
- deterministic staged copying and portable Markdown;
- XML/SVG parsing, path confinement, regular-file and identity checks;
- rejection of script, event-handler, foreign-object, and external-resource
  behavior; and
- reader-visible ancillary data or tabular/text alternatives where the source
  report declares them.

Do not reinterpret or regenerate CAL-09 science. The task is to admit and
faithfully assemble the already reviewed draft source.

## Security And Safety

- Work offline and never fetch or dereference SVG resources.
- Parse and validate SVG as data; do not execute it.
- Reject links or elements that could load code or external content.
- Use confined regular files and fail closed on symlinks or special files.
- Stage only to authorized disposable roots.
- Prepare all transaction outputs before replacement and recover exactly after
  injected or real failure.
- Never infer human approval from source validity, a review lock, or a
  successful build.

All build and check operations are repeatable. The admission transaction must
stage complete replacement bytes before mutation, use the established atomic
transaction mechanism, and leave either the exact old generation or the exact
new generation—never a mixture. An interrupted or injected failure must be
recoverable by rerunning the same typed request after the tool verifies current
generation consistency.

The preview may be deleted and rebuilt because it is derived, ignored output.
Do not use Git restoration commands on user work. If execution encounters an
unexpected dirty overlap, stop, preserve it, and reconcile before proceeding.

## Surprises & Discoveries

- The V2 deterministic builder already renders admitted reports; the missing
  lifecycle capability is typed admission of a new source.
- The existing native figure schema generates one bar-chart kind. CAL-09's
  eight already-reviewed SVG time-series figures currently exist only as
  public-safe research objects and need a secure inline assembly path.
- Matplotlib emits a document-level default CSS rule. Safe assembly required
  recognizing only that exact inert rule and translating it to equivalent
  inherited presentation attributes while rejecting all other style elements.
- The initially selected `quick-xml` release carried published advisories.
  Upgrading to `0.41.0` closed them before disposition.
- Admission was first exercised before schema-v2 root binding existed.
  Reconstructing the uncommitted transition from the scaffold baseline produced
  a clean two-receipt v2 chronology instead of preserving weaker evidence.
- Full report assembly needs the complete `usersum` prerequisite tree in a
  staging root, even though only the assurance report subtree is emitted.

## Decision Log

- Decision: use `target/assurance-preview/` as the stable human-inspection root.
  Rationale: it has the production-compatible `usersum/` shape while remaining
  disposable, ignored, and nonpublic.
- Decision: admit CAL-09 and render all three V2 reports in one package.
  Rationale: the real `--all` consumer proves both new admission and catalog
  completeness; isolated fixtures cannot close either claim.
- Decision: classify the work as Critical.
  Rationale: it changes trust-root generation, schemas, transactional mutation,
  assembly security, and a broadly consumed CLI.
- Decision: require schema-v2 receipts to bind exact old and new report roots
  while continuing to decode archived schema-v1 receipts byte-identically.
  Rationale: admission introduces a report that has no old root, which cannot
  be represented honestly by the earlier implicit-root contract.
- Decision: isolate check-mode candidates in atomically created,
  invocation-owned operating-system temporary directories.
  Rationale: dry runs must never create state that recovery could activate.
- Decision: preserve exact retained SVG bytes as identified research objects
  and stage a separately sanitized inline representation.
  Rationale: custody and safe reader rendering are distinct obligations.

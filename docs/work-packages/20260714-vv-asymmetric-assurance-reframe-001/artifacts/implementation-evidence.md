# Implementation Evidence

Status: `FINAL`

## Outcome

Static: The strategy now separates three questions and their owners:

1. openWEPP maintainers and the named release authority accept or reject exact
   software-verification obligations against declared requirements and
   tolerances;
2. the scientific program and independent domain reviewers publish dated,
   revisable empirical corroboration over a bounded tested domain; and
3. the hydrologist, practitioner, agency, or other named decision owner decides
   whether that evidence is adequate for a specific application.

Static: The nuclear precedent is bounded to closable requirements, graded
rigor, configuration identity, uncertainty, and review. The strategy explicitly
distinguishes quantitative V&V evidence from a binary acceptance or
authorization decision and does not import a facility-licensing conclusion into
an open natural system.

Static: A release is now defined as an exact software realization whose required
verification obligations pass, accompanied by an immutable as-of empirical
corroboration snapshot. It is not a terminal scientific qualification event.

## Public Dossier Changes

Static: The dossier opens with an evidence summary rather than a decision
summary. It uses separate verification and empirical status vocabularies and
prohibits recombining them into an openWEPP-issued use disposition.

Static: The application-context worksheet now supplies a copyable ownership
block, side-by-side application-versus-dossier comparison table, required
scientific coverage rows, and a separate institutional decision record. Any
resulting assessment uses that decision owner's terminology and approval
process; openWEPP does not create a third status ladder.

Static: Review remediation makes empirical characterization fail-closed with
respect to relevant verification. An implementation mismatch on a failed,
blocked, or unrun result surface remains negative implementation evidence and
cannot be called empirical contradiction. A forceful contradiction status
requires a verified result surface.

Static: The content-bound audit kernel is preserved. Every claim-bearing input,
configuration, transformation, output, figure, log, review, and material failed
or superseded artifact still requires a stable location, scientific role,
content identity, availability posture, and production/use identity. A manual
Markdown, JSON, or YAML manifest remains sufficient.

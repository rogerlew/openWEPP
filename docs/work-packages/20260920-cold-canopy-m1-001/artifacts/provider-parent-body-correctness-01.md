## Findings

1. **High — three source-extraction locators name accessors that do not exist, and the authenticated GSI value is still emitted from a literal.** In `m1_fixed_sequence_provider.rs:443-477`, the exposure, topology, and controller joins claim `FixedSequenceSourceAdapter::original_exposure_for_provider`, `FixedSequenceSourceAdapter::original_topology_for_provider`, and `FixedSequenceSourceAdapter::controller_policy_for_provider`. Repository search finds those names only in the emitted locator strings and the matching test oracle; no such methods are defined or invoked. The values are constructed inline, while the controller actually invokes the differently named free function `openwepp_land_surface_energy::m1_fixed_sequence_controller_policy`. At `:445-462` the retained endpoint constructor and its GSI are evaluated and included in the complete-output hash, but `:470` still writes `"3ff0000000000000"` rather than encoding the selected `/gsi` value. SC-VEGETATION-001:3392-3405 requires the named retained constructor/accessor to execute, the complete output to be authenticated, the output pointer to be applied, and the extracted scalar to be encoded. Current payload equality cannot prove those operations because the independent oracle repeats the same nonexistent names and GSI constant at `m1_fixed_sequence_provider_controls.rs:442-490`. Define and invoke the private typed accessors named by the locators (or change each locator to the truthful invoked accessor), derive every join value from that accessor's selected output, and add an independent equality control between the retained endpoint GSI bits and the emitted join/receipt value. Otherwise an accessor refactor or newly authorized retained output can leave the receipt scalar disconnected from the authenticated output.

2. **High — the admitted beginning-owner digest is built from a parallel, noncanonical six-owner serializer.** `m1_receiver.rs:450-490` locally assembles the non-snow owner bytes. In particular, `surface_liquid` is only `DirectSurfaceLiquidOwnedState::canonical_bytes` at `:454-485`; the existing canonical V11 parent owner route wraps that persistent state in `OPENWEPP_SURFACE_LIQUID_COMPLETE_OWNER_PROJECTION_V2` and includes `wb14_parent_working_state` in `canonical_owner_bytes.rs:1223-1258`. The current beginning digest therefore differs from the repository's canonical complete-owner representation even when the WB14 state is `None`. The soil V1 serialization is presently byte-equivalent, but it also bypasses the owner route `DirectSoilThermalResident::canonical_active_owner_bytes` (`v9_real_consumer_shadow/v10_soil_thermal_v2.rs:618-623`). The established complete-parent entry is `DirectV10RealConsumerShadow::canonical_v11_parent_owner_state_bytes` at `canonical_owner_bytes.rs:1149-1157`, backed by the per-owner construction at `:1182-1277`; factor or expose its non-snow canonical encoders for the M1 owner state rather than maintaining another representation. The snow path is correct: `m1_receiver.rs:409-418` uses the retained Stage-3 initializer and `v11_covered/owner_finalization.rs:1305-1318` through the existing re-export, and the inactive snow bytes remain stored. Strengthen the positive control to compare all seven exact caller bytes against independently constructed canonical owner bytes, including the surface wrapper, before accepting the coupled clock. A seven-key map and unchanged snow alone do not establish the required non-circular canonical beginning-owner set.

3. **Medium — provider-specific caller initialization duplicates the normal caller constructor.** `M1CallerState::beginning_from_provider_reservoirs` at `m1_receiver.rs:377-439` repeats the M1 configuration identity, M1 owner construction, thermal initialization, Stage-3 snow initialization, owner cloning, and caller continuity fields from `M1CallerState::beginning` at `:586-660`. This is substantial owner-initialization duplication at the exact boundary whose equality the provider is meant to prove; later changes can silently make the diagnostic caller differ from the actual physical caller. Extract one private shared initialization path that accepts the already validated reservoir rows, and have both entry points call it. The provider-specific entry may derive its cycle phase rows first, but it must not own a second copy of owner construction or inactive-snow initialization.

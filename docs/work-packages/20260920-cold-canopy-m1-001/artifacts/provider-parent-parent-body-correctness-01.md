# COLD-CANOPY-M1 partial complete-parent body — correctness review 01

**Verdict: HOLD.** The authored segment-lineage, solver/GSI, native transaction, and slab-staging direction is partly sound, but the current support transaction namespace cannot execute against the retained BGC beginning and will later collide with the persistent parent revision. Physical solver failures are also misclassified as provider admission failures, the native context remains bound to the bootstrap forcing receipt, and the released controls' completion/raw-evidence APIs are still absent.

**Evidence class: Static.** Independent review of frozen canonical 760-entry source aggregate `067138e680d3b0953b1f9a181ba779fec18aeced3db0f54f30182d63cc170fdf` and the separately frozen required-full recorder. Supplied compile13 remains expected-red with 56 errors; no test or physical command was run by this reviewer.

## Findings

1. **High — `ordinal + 1` is not a lawful support transaction namespace and makes the first BGC candidate stale.** `m1_receiver.rs:2011-2019` constructs `TransactionId(support + 1)`. The retained caller begins from an existing vegetation/BGC transaction lineage (the endpoint fixture is not transaction zero), while canonical BGC construction rejects any transaction `<= beginning.last_transaction_id` (`openwepp-biogeochemistry/src/lib.rs:271-275`). Thus support zero's ID `1` cannot reach the authored BGC seam. Even if that initial failure were bypassed, support ordinal 41 yields ID 42, which collides with the persistent parent revision after the first parent and violates the required checked-support/persistent-parent distinction. Derive a checked support identity from authenticated run/cycle/support authority in a namespace guaranteed to be positive, unique, greater than the actual BGC candidate predecessor where required, and disjoint from every persistent parent revision. Do not derive native/BGC/material IDs independently: the same checked ID must bind all of them. Add controls beyond parent zero so the first later-parent collision is exercised.

2. **High — BGC segment candidates still advance serialized persistent lineage on every support, contrary to the canonical segment/parent split.** `m1_receiver.rs:658-660,685-687` constructs a canonical `BiogeochemistryOwnerCandidate` and installs its ending directly into staged owners. Canonical BGC construction sets `ending.last_transaction_id` to the support transaction (`openwepp-biogeochemistry/src/lib.rs:352`). `SC-VEGETATIONTRANSACTION-001.md:350-356` says segment candidates are staged only and cannot increment or commit the persistent parent transaction; its shared-resource rule at `:359-375` separately requires each segment transition to carry the current staged shared inventory and exact candidate/receipt lineage. Preserve the validated support-bound BGC receipt/candidate, but project its physical layers/receivers into a staged parent-segment owner with the admitted parent lineage unchanged, analogous to `M1ParentSegmentCandidate`. Finalization may then use the existing lineage-only BGC transition. The projection must follow successful canonical BGC candidate validation; it cannot skip that validation or rewrite receipt identities. The released control asserts staged M1/stratum lineage and final BGC lineage/physical preservation, but does **not** currently assert staged BGC `last_transaction_id`; add that direct assertion so this defect cannot hide behind `parent_only_counters()`.

3. **High — canonical solver/domain failures are collapsed into metadata error `VEG-E-144`.** `m1_fixed_sequence_provider.rs:787-790` maps both `solve_m1_coupled_column` and `M1PreparedCallerContext::new` failures to unit `ProviderError`. `ProviderError` identifies provider admission/custody, while these failures are typed physical/domain/binding errors. This loses stage/reason taxonomy and lets a physical failure masquerade as a bad provider. Add an execution-error variant that preserves the actual `LandSurfaceEnergyError`/`M1CoupledError` source (or the existing receiver wrapper) without changing numerical response. Reserve `ProviderError` for provider parsing/admission/source authority.

4. **High — the provider support enters native execution with a bootstrap forcing receipt/context.** `m1_fixed_sequence_provider.rs:815-824` creates a fresh `endpoint_fixture()` for every record. `native_fixture_from_current` replaces owner state but reconstructs its receipt from `bootstrap.forcing.forcing_sha256`, `bootstrap.receipt.forcing()`, and the bootstrap vegetation/LSE configuration (`m1_receiver.rs:564-617`). The canonical solve correctly receives the record overrides and authenticated GSI, but the native transaction is therefore not authenticated to the same provider record/parent-forcing context. Build the native context/receipt from the admitted support's actual provider forcing authority and the prepared input/current owners. Reusing frozen geometry/configuration helpers is legitimate; retaining the unrelated endpoint forcing receipt is not. The old direct-fixture wrapper may retain bootstrap GSI for its accepted original60 scope, while the provider path must remain explicit.

5. **High — each support resets evolving LSE/soil-thermal beginning operands to the retained original input.** `m1_coupled_expected_red.rs:141-144` deserializes the complete original `CoveredColumnInputs`. The provider driver at `m1_fixed_sequence_provider.rs:773-786` changes only air temperature, humidity, longwave, top rain, liquid enthalpy, and the two M/H reservoirs before solving. `CoveredColumnInputs` also carries the mutable ground beginning (`ground_surface_temperature_k` and `ground.soil_nodes`; `solver_covered_evaluation.rs:258-282`), and the covered evaluator consumes those node temperatures in its soil-flux/ending solve. The authorization requires each accepted owner ending to become the next staged beginning. Retaining immutable geometry, topology, coefficients, and prescribed conditions from the original fixture is valid; resetting mutable ground/soil/hydrology beginning operands is not. Add a fieldwise current-owner projection before every solve and a consecutive-support control proving every mutable beginning operand equals the prior accepted staged LSE/soil-thermal/hydrology owner while the immutable original fields remain exact.

6. **High — the bounded parent implementation is still structurally incomplete.** The source has no released-control APIs for raw support outcomes (reservoir/resource debit/flux/transition/complete-candidate/material/BGC/owner/slab evidence), direct caller staged/clock/counter/capability access, sealed finalized owners, typed replay, or consuming `complete_parent`. Compile13's missing-body/API errors are therefore substantive expected-red evidence, not a build-only nuisance. Complete these using actual producer-owned structures and the canonical V11 finalization/ownership-transfer seam; accessors may expose existing state but may not synthesize reports, receipts, errors, or owner sets. Refresh complete source/build custody before any control run. The ten-member extraction manifest was independently rehashed by root with zero mismatches and is not stale; new runtime source is covered by the full frozen source snapshot rather than falsely added as an extraction dependency.

- The provider path forwards the admitted binary64 GSI through `advance_m1_caller_support_with_gsi` (`m1_fixed_sequence_provider.rs:812-824`; `m1_receiver.rs:1988-2019`). The historical wrapper retains fixture GSI only for its existing direct-fixture scope.
- Native transaction/contributor construction now uses the segment support ID instead of the persistent M1 parent revision (`m1_receiver.rs:2021-2027,2055-2063,2127-2168`). The namespace defect above must be fixed, but the single-source propagation direction is correct.
- `advance_fixed_sequence_support` stages on a caller clone, constructs the exact record support and hard-boundary reduction, invokes real `CoupledSlabCandidateV1`/`accept_slab`, and replaces the caller only after acceptance (`m1_fixed_sequence_provider.rs:802-890`). The custody ledger's equal debit/credit digests are required by `LedgerEntryV1`; the accepted slab separately seals ending owners, so that equality is not a finding.

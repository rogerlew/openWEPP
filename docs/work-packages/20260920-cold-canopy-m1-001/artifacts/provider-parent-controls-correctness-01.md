## Findings

1. **High — the controls do not independently authenticate either complete frozen cycle or the emitted projection.** `m1_fixed_sequence_provider_controls.rs:150-196` validates only the separate continuous-source JSON. It never compares the adapter-emitted payload's segments, records, breakpoint positions, or override bits with that source. `:204-208` exposes no cycle selector, while `:238-270` admits only one payload and checks only records 0/29 and parent 0. The second required cycle, its distinct initial phase records, all of its breakpoints, record 4319, parent 143, day mapping, and the exact 30-record slices are absent. `:281` even treats cycle ordinal 1 as a poison in the sole exercised payload. A mutually wrong generator and validator can therefore pass while emitting a projection unrelated to the frozen source. Add an independent source-to-payload expansion oracle for both cycle ordinals, every breakpoint and override bit pattern, all 4320 ordered records, all 144 parent slices, exact day mapping, and both distinct initial-phase sets.

2. **High — two of the four provider identity/receipt domains have no independent known answer.** `:109-147` derives only the run identity and the first GSI-support receipt; `:246-261` asserts only those two. There is no independent calendar-receipt preimage/result for either cycle and no parent-forcing-receipt preimage/result binding the full-projection content hash, parent support, 30 exact ordered records, and 30 ordered GSI receipt identities. This misses the contract's four-domain known-answer obligation and cannot detect field order, width, framing, cycle, or parent-slice drift in those domains.

3. **High — the seven source joins are tested against production-generated bytes rather than independent expected values.** `:243-246` obtains the baseline payload from `FixedSequenceSourceAdapter`; `:298-326` then mutates fields in that payload and asks the production admission boundary to reject them. No control independently fixes each join's expected source path/hash, locator kind and locator, value kind, and extracted value. Even the run oracle reads source and implementation hashes back from the generated payload at `:109-123`; it does not establish that they are the retained bytes. The GSI oracle similarly hashes the generated join object at `:128-146`. Add independent expected rows for all seven joins and the adapter dependency/output hashes, while retaining real admission-API mutation refusal.

4. **High — canonical JSON coverage is incomplete for the specified byte grammar.** The byte controls at `:340-357` cover duplicate top-level key, leading whitespace, leading-zero integer, and CRLF only. They do not cover ASCII-subset enforcement, non-ASCII refusal, unescaped slash, exact quote/backslash escaping, lowercase `\\u00xx` control escapes, rejection of short/control or alternate escape spellings, nested duplicate/unknown keys, or binary64 string width/case/digit failures. The local oracle's `serde_json::to_string` at `:45-75` is not itself proof of the contract's bespoke escape grammar. Add small independent encoding vectors plus actual parser refusal cases.

5. **High — provider refusal is not yet proved at the real caller staging/publication boundary.** `FixedSequenceAdmissionAudit` is supplied to the same API under test and `:210-229`, `:387-395` inspect only its counters. Neither API receives an `M1CallerState`, coupled clock, or owner envelopes, so these checks cannot prove that real owner bytes and parent publication remain unchanged on refusal. Keep these counters as supplemental instrumentation, but add caller-owned pre/post snapshots through the actual provider-to-parent admission boundary for each required poison.

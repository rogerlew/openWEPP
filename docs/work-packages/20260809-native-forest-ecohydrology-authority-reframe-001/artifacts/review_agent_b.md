### `SCI-B-001` — HIGH — successor instructions still require an impossible closure-package release

The successor package correctly says that the authority-closure package ended
`executed-hold`, that its universal-value/state premise is superseded, and that
the successor remains held only on schema/constitutive authority and its own
contract-first gate
(`docs/work-packages/20260808-rhessys-east-coast-coupled-vegetation-slice-001/package.md:78-92`).
Its active kickoff prompt, however, still instructs the future executor to
verify the authority-closure predecessor's "explicit successor release" and to
consume that package's "exact admitted boundary"
(`docs/work-packages/20260808-rhessys-east-coast-coupled-vegetation-slice-001/prompts/active/20260808-rhessys-east-coast-coupled-vegetation-slice-001_kickoff_agent_prompt.md:130-137`).
That predecessor did not release the successor, and the present reframe exists
specifically to supersede part of its boundary. The prompt can therefore
deadlock or cause a future executor to consume the wrong authority premise.

Proposed disposition: `accepted`. Amend only those execution steps so they
require the closure package's retained source/gap evidence and terminal
identity, then require this reframe's accepted terminal disposition as the
authority for caller-owned values/state and the corrected native-forest target.
Do not require a release that the executed-hold predecessor never issued.

### `SCI-B-002` — HIGH — calibration-readiness evidence does not use the required orthogonal statuses

The package is parameterized-science authority work, but
`artifacts/calibration-readiness-matrix.md:3-9` reports only a free-form surface
table. It omits the required top-level `science_implementation_status`,
`calibration_evidence_status`, and `identifiability_status` fields and does not
disposition the complete readiness-obligation set. This obscures the important
distinction that v4 admits a boundary while constitutive science remains
unimplemented and calibration is not ready.

Proposed disposition: `accepted`. Add the three governed fields, expected here
to be `AUTHORITY_MISSING`, `NOT_CALIBRATION_READY`, and `NOT_ASSESSED`, and a
`PASS`/`BLOCKED`/`NOT_APPLICABLE` row for every readiness obligation with an
evidence path and rationale. Preserve the package's no-calibration/no-validation
claim.

### `SCI-B-003` — LOW — stale version wording weakens the v4 failure boundary

fallback prohibition inside contract version 4. Nearby canopy-snow text was

on an implementation-authoritative guard.

Proposed disposition: `accepted`. Change the sentence to state that version 4
preserves the version-2 prohibition.

## Adversary Contract

The executor optimizes lexicographically:

1. preserve governance, evidence truth, and every selected obligation;
2. finish the bounded package without avoidable operator intervention; and
3. minimize wall time, compute, duplicate work, and changed bytes.

The executor may reject an unnecessary command, but it may not downgrade risk,
suppress a selected gate, edit policy, treat stale evidence as current, or
represent an unrun check as PASS. Before each mutating or gate-running command,
it records the command's purpose and invalidation scope. A successful gate is
not repeated unless a later edit invalidates its inputs. A failure is repaired
only when the cause lies inside the write set; otherwise execution stops
fail-closed with a named boundary.

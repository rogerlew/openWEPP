## Reachability and accepted numerical design

is available before Stage-3 evaluation; each coupling iteration can bind that
output to its flux, preview, hints and convergence operands; convergence can
then produce an immutable selection receipt; and `terminal_event.rs` can add
the terminal transition, ledger and hydrology-complete joint only to the
selected trial. A later admission check occurs before any provider call.

## Blocking findings

1. **Critical — the census replay classification is not AST- or
   type-backed and makes false normative claims.** `replay_class` searches the
   complete source-file text for `replay_bytes`, `receipt_sha256`, `digest(` or
   `framed_sha256`; it does not inspect the selected declaration's native seal
   or preimage. Consequently `CoveredCarrierPhaseResultV1` is classified as
   class 1 merely because it has WB14 replay byte fields, although no native
   replay wire exists for the complete result. Conversely many unrelated
   declarations in a file are classified as class 2 because some other type
   in that file has a seal. The adapter normatively says class-1 values embed
   their exact native type tag, domain, digest and bytes. Those values do not
   exist for the complete carrier result. This makes the requested provider
   evidence impossible to encode as specified.

2. **Critical — the census is not a complete recursive live-type census.** Its
   manually curated `TARGETS` list stops at many named nested types, including
   `OfeId`, `TileId`, `SoilLayerId`, `ResourceOwnerId`, `TransactionId`,
   `Sha256Digest`, `BandDirectionalFluxes`, `DirectV10RealConsumerShadow`,
   `DirectSnowStage3PersistentState`, `UncommittedV8VegetationCandidate`,
   `BiogeochemistryOwnerCandidate` and the payload types of
   `CoveredV8PhysicalOwner`. Those types are required by the carrier result,
   owner envelope, lower boundary, precipitation, soil snapshot and joint
   evidence. Their declarations, variants, native wires, visibility and
   fingerprints are absent. The generator only asserts that every manually
   named target was found; it never discovers or rejects an uncensused nested
   dependency. The byte-comparison guard therefore faithfully guards an
   incomplete census rather than the closed declaration graph.

3. **Critical — `carrier_phase_v4` still defers the central field-selection
   judgment to implementation.** It asks for a “provider-owned projection of
   `CoveredCarrierPhaseResultV1`” but does not enumerate that projection or its
   exact tags. The live result contains `transition`, whose live declaration
   includes both beginning and ending joints, and `ending_candidates`, whose
   joint likewise requires an ownership decision. V4 simultaneously requires
   provider evidence to exclude the hydrology-complete joint. There is no
   uniquely specified subset or transformation that reconciles those rules.
   An implementer must decide which fields and nested fields survive, exactly
   the semantic-adapter discretion the V4 gate forbids.

4. **Critical — no complete census-derived adapters are actually frozen.** For
   class-3 values the schema says to encode every census field recursively,
   but it supplies neither per-type framed tags/domains nor schemas for the
   uncensused nested types. For class-2 values it authorizes a later extractor
   even when the generator has not identified a declaration-specific native
   digest function, domain or preimage. The census column is explicitly only
   “native validator/digest candidates” and its function search is another
   source-file substring heuristic; for example it attributes multiple seals
   and digests from the whole physical-ledger module to each receipt. Thus the
   authority does not establish whether to extract an existing native
   preimage or create a diagnostic adapter for each receipt, and it does not
   define one unique byte stream.

5. **Major — the complete-evidence/cardinality claims cannot be validated from
   the frozen wire.** The high-level keys correctly prevent substituting a
   discarded coupling iteration for the selected one, and the pair schema
   names exactly three selected trial digests. But because a carrier arena
   entry has neither a realizable native replay nor a complete adapter, those
   keys cannot resolve to all forcing, topology, prescribed/generated amounts,
   rates, `q_ss`, WB14 and snow-soil receipts. Pair cardinality is closed only
   for opaque record digests, not for the complete evidence each digest is
   claimed to bind. The known energy discrepancy and the absence of terminal
   ingress therefore cannot yet be independently reconstructed from the
   authorized records.

6. **Major — the declared owner-module boundary is incomplete relative to the
   census graph.** V4 names selected owner files, but the uncensused private
   nested owner types include declarations outside that list. Until recursive
   discovery identifies every private payload and its actual owning module,
   the authority cannot know which test-only replay functions are necessary or
   prove that the six-file forwarding path can obtain every promised receipt.

## Disposition

V4 preserves the accepted pair/floor/cardinality/error design and corrects the
conceptual V3 ownership placement of terminal outcomes and the accepted-event
heat receipt. It does not satisfy the required census-first wire gate. A
successor must recursively close the type graph; derive replay class from each
type's actual seal/preimage rather than file text; enumerate the provider
projection exactly; and generate complete per-type adapter tags and encodings.

**HOLD**. The two-GO gate must stop before an exact-file implementation intent
or any source edit. The authoritative physical result remains
`Stage3(TerminalNumerics(BelowCarrierDomain))`, and
